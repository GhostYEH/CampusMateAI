### 第一层：事件层——发生了什么

系统先把不同来源的数据转成统一事件，例如：

- 完成了一次专注
- 创建或完成了任务
- 同步了课程和课表
- 发现了考试
- 收到校园通知
- 创建了个人目标
- 更新了目标进度
- 接受或撤销了行动计划

事件层保存的是事实，不直接下判断。

------

### 第二层：状态层——现在是什么情况

系统把一段时间内的事实投影成三类状态。

#### CORE

描述基础活动：

- 当前任务数量
- 截止日期分布
- 学习与专注活动
- 课程参与
- 数据源是否健康

#### ACADEMIC

描述学业环境：

- 课程负载
- 成绩观察
- 学分进度
- 考试暴露
- 课表负载
- 学业目标

#### WORLD

描述大学生当前整体校园状态：

- 工作负载
- 日程冲突
- 学业进展
- 专注节律
- 目标进展
- 执行一致性
- 成长动量
- 用户主动设置的偏好

每个状态都不是永久标签，而是一个有时间范围的判断。

------

### 第三层：不确定性与证据——为什么这样判断

系统不会只返回：

```
你最近压力很高
```

而会维护类似信息：

```
状态：未来三天任务较集中
置信度：0.82
数据质量：PARTIAL
有效期：未来一小时
解释：存在两个临近截止任务和一个考试
证据：对应任务、考试和同步事件
```

数据不足时返回：

- `PARTIAL`
- `STALE`
- `UNAVAILABLE`

而不是假装自己知道。

------

### 第四层：预测——接下来来可能发生什么

当前支持预测：

- 截止完成风险
- 未来工作负载
- 日程冲突风险
- 目标进展趋势
- 专注节律连续性

目前预测是确定性规则估计，不是神经网络预测。

答辩时可以说：

> 第一阶段优先选择确定性基线，是为了建立可解释、可验证的预测闭环；后续真实数据积累后，再用统计模型或小模型替换部分估计器，并通过 Brier Score 和 ECE 做校准。

------

### 第五层：反事实模拟——如果换一个方案会怎样

系统可以比较：

- 如果今晚多安排 30 分钟专注；
- 如果把非紧急任务移动到周末；
- 如果接受当前计划；
- 如果降低某天负载；
- 如果调整目标日期；
- 如果暂停一个数据源。

模拟是只读的，不会真的修改任务。

它回答的是：

> 在当前假设下，方案可能带来什么变化？

不是：

> 这个方案一定能带来什么结果。

------

### 第六层：行动闭环——接下来怎么做

系统结合：

- 当前 WORLD 状态
- ACADEMIC 状态
- Forecast
- 用户目标
- 任务、考试和通知
- 用户可用时间

生成行动计划。

然后由用户：

```
接受
→ 执行
→ 创建真实任务
→ 反馈
→ 撤销或重新规划
→ 新事件进入世界模型
```

这就是完整闭环。

------

## 它和普通学生画像有什么区别

普通学生画像通常是静态字段：

```
专业
年级
课程
兴趣
历史成绩
```

你的世界模型还有：

- 状态随时间变化；
- 状态有有效期；
- 状态有置信度；
- 状态能追溯证据；
- 数据不足会主动放弃判断；
- 可以预测未来风险；
- 可以模拟不同方案；
- 可以产生可执行计划；
- 用户可以纠正、暂停来源和删除数据；
- 行动结果会再次更新状态。

一句话概括：

> 学生画像描述“这个人是谁”，学生世界模型描述“这个人当前处于什么校园情境、为什么这样判断、下一步可能发生什么、采用不同方案可能有什么变化”。

------

## 它和 RAG、LLM、CPM 的关系

可以用这个结构讲：

```
RAG：告诉 CPM 学校规则是什么
世界模型：告诉 CPM 学生当前是什么情况
Forecast：告诉 CPM 接下来有哪些风险
Simulation：告诉 CPM 不同方案可能有什么变化
Planner：把判断转成行动
LLM：把结果组织成自然语言
CPM：把所有能力统一呈现给学生
```

例如学生问：

> 奖学金材料什么时候准备比较合适？

系统可以这样工作：

1. RAG 查到奖学金申请材料和正式截止时间。
2. 世界模型发现学生未来三天任务集中。
3. 目标状态显示学生正在准备奖学金申请。
4. Forecast 判断临近日期负载较高。
5. Planner 建议今天先整理成绩单，周末填写申请表。
6. CPM 用自然语言解释建议，并把校园规定与个性化建议明确分开。

这就是你的核心创新点：

> 不只是“回答问题”，而是把校园事实、个人状态和可执行行动连接起来。
