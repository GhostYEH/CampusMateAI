# CampusMateAI 行为识别 V3.4 离线过渡基线设计

## 1. 目的与定位

本阶段建立一套可复现的学生行为识别训练、评估与 ONNX 导出链路，验证公开课堂数据能否改善 CampusMateAI 对阅读、书写和手机交互的区分能力。

本阶段是路线文档中的 **V3.4 离线过渡基线**，不是正式 V4，也不直接替换 Android 当前 V3.2 模型。由于用户明确要求暂时跳过真机测试，候选模型只能被标记为离线研究产物；完成真实前置摄像头评测前，不启用基于该模型的正式分神提醒。

模型只识别可观察行为。是否处于学习状态、是否可能分神以及是否提醒，仍由产品状态机结合持续时间、任务上下文、Presence、头部和眼睛信号决定。

## 2. 当前基线证据

Android 当前行为模型为 ResNet18 单帧二分类模型：

- 输入：`1 x 3 x 224 x 224`，RGB、ImageNet mean/std、NCHW；
- 输出：`IDLE`、`VISIBLE_STUDY`；
- 模型资产：`campusmate_visible_study_v32.onnx`；
- 推理引擎虽然接收帧窗口，但仅使用最新一帧。

在 SCB-Dataset3 大学课堂数据中，按阅读、书写、手机交互和睡觉四类均衡抽取 1,000 个学生框，并使用与 Android 对齐的预处理运行 V3.2，得到以下诊断结果：

| 原始行为 | 二分类期望 | V3.2 二分类正确率 |
|---|---|---:|
| READ | VISIBLE_STUDY | 51.2% |
| WRITE | VISIBLE_STUDY | 42.0% |
| PHONE_INTERACTION | IDLE | 50.0% |
| SLEEP | IDLE | 36.4% |
| 总体 | — | 44.9% |

该结果只衡量公开课堂人物裁剪域，不代表手机前摄最终精度，但足以说明现有模型在关键行为上存在明显提升空间。

## 3. 数据范围

原始数据保持只读，不在 `F:\数据集` 内覆盖、修复或重排文件。所有清洗结果、清单和派生裁剪写入项目管理的工作目录，并记录来源路径和哈希。

首轮使用：

1. `F:\数据集\SCB5-Handrise-Read-write-2024-9-17`
   - 6,864 张图片；
   - 47,372 个标注框；
   - 行为为举手、阅读、书写。
2. `F:\数据集\SCB_BowTurnHead_20250509\SCB5-Turn-Bow-Head-2024-9-17`
   - 2,410 张图片；
   - 16,118 个标注框；
   - 行为为低头、转头。
3. `F:\数据集\0.671k_university_yolo_Dataset`
   - 671 张图片，训练 529、验证 142；
   - 19,768 个标注框；
   - 类别顺序：`Raise_hand`、`Read`、`Write`、`OnPhone`、`Bow_head`、`Sleep`。

首轮排除：

- `50salads`：厨房动作特征，与学习场景不匹配；
- SCB 教师行为数据：主要识别教师、讲台、屏幕和黑板；
- `YOLO.zip` 中的源码、训练结果和未知 `.pt` 权重；
- 来源、许可证或类别映射无法确认的数据。

已发现的异常标注包括：

- Handrise/Read/Write 验证集有 2 个坐标越界框；
- SCB-Dataset3 中 `40010060.txt`、`40010061.txt` 各有一个负宽度框；
- 教师数据另有 4 个越界框，但教师数据不进入首轮训练。

负宽度、负高度或无有效面积的框从派生清单剔除；轻微超出图像边界的合法框裁剪到边界。所有修复都写入审计报告。

## 4. 标签与语义

首轮模型输出四个可观察行为：

```text
READ
WRITE
PHONE_INTERACTION
NO_VISIBLE_STUDY
```

语义约束：

- `PHONE_INTERACTION` 只表示观察到手机交互，不表示一定分神；
- `NO_VISIBLE_STUDY` 表示没有观察到当前模型支持的明确学习动作，不等同于不认真；
- `UNCERTAIN` 不作为缺少数据支持的强制训练类别，而由置信度校准、Top-1/Top-2 margin、画面质量和信号冲突产生；
- `RAISE_HAND` 在大学子集中只有 6 个框，且与个人自习场景关系弱，不作为主类别；
- `HEAD_DOWN`、`HEAD_TURN` 进入困难样本和辅助评估，不直接作为分神结论；
- `SLEEP` 用于疲劳/休息专项评估，正式判断需结合眼睛、头部与持续时间。

将公开数据映射到 `NO_VISIBLE_STUDY` 时必须保守。低头、转头、睡觉等样本可作为候选负类或困难样本，但需要分别报告消融结果，避免把正常低头写字和思考错误训练成分神。

## 5. 数据处理与防泄漏

数据管线分为五个独立步骤：审计、规范化、分组划分、人物裁剪、训练索引生成。

1. **审计**：检查图片可读性、YOLO 行格式、坐标范围、图片标签配对、类别 ID、空标签和 SHA-256 重复项。
2. **规范化**：只在派生目录生成修复标签；保留原始标签、修复原因和新旧值。
3. **分组划分**：不能将近邻视频帧随机拆到不同数据分区。根据文件名前缀、连续编号和感知哈希形成场景组；无法可靠推断时采用更保守的大组划分。
4. **人物裁剪**：以行为框为基础向外扩展，尽量保留头、肩、双手和桌面上下文；越界部分安全裁剪。
5. **训练索引**：输出稳定、可复现、带来源和组 ID 的 CSV/JSONL 清单，不依赖运行时扫描顺序。

最终保留 train、validation、test 三套清单。validation 用于模型、阈值和拒识选择；test 在方案锁定后只执行最终评估。

## 6. 模型候选与选型

首选模型为 MobileNetV3-Small 单帧分类器，输入保持 `224 x 224`。选择原因：

- 与项目路线的 V4 编码器方向一致；
- 比 ResNet18 更适合端侧；
- 后续可直接作为 GRU/TCN 的特征编码器；
- 当前数据是静态图片，先建立单帧基线比伪造时序样本更可靠。

至少比较三种输入策略：

1. 完整画面；
2. 扩展人物/上半身 ROI；
3. 人物 ROI 与低分辨率全局上下文融合。

首轮实现以 MobileNetV3-Small ROI 分类器为主基线。完整画面必须作为对照；双路融合只有在独立 validation 上显著提升关键指标且复杂度可接受时才保留。

训练候选策略包括 class-weighted cross entropy、balanced sampler、focal loss、label smoothing 和 hard-negative mining。一次只改变有限变量，并保存完整配置和随机种子。

## 7. 置信度与产品状态

模型 logits 先经过温度缩放，再根据每类阈值、Top-1/Top-2 margin 和输入质量执行拒识：

```text
证据充分 -> 显式行为
置信度低、margin 小、画面质量差或信号冲突 -> UNCERTAIN
```

候选行为进入现有时间窗口，不允许单帧触发提醒。规则基线：

- `PHONE_INTERACTION`：连续 5～8 秒后成为候选事件；
- 持续看向其他方向：8～12 秒，并结合头部姿态和任务上下文；
- `NO_VISIBLE_STUDY`：连续 20～30 秒后才允许进入暂停候选；
- 疲劳、疑似睡觉或低眼睛睁开概率：使用休息文案，不使用分神文案；
- `UNCERTAIN`：不提醒；
- 提醒冷却：默认 3 分钟。

手机交互只有在任务上下文不需要手机且证据持续时，才能成为高可信分神候选。

## 8. 工程边界与失败处理

首轮新增内容集中在 `ml/behavior_recognition`，包括数据审计、派生清单、训练、评估、ONNX 导出和模型卡。原始大数据、派生图片、checkpoint 和训练日志不提交 Git，只提交脚本、小型配置、清单摘要和报告模板。

失败处理：

- 数据源缺失：明确报出缺失路径，不静默跳过整个数据源；
- 图片损坏：隔离并写入审计报告；
- 标签异常：按规则修复或剔除，并保留原因；
- 类别映射不明确：停止该数据源导入，不猜测；
- ONNX 数值不一致：候选模型不得进入 Android 资产；
- 模型加载或输出异常：Android 保持 V3.2，不把异常当作分神；
- ROI 不可用：后续运行时应退回完整画面并产生质量标记。

## 9. 评估与验收

模型层至少报告：

- Accuracy、Macro-F1、Balanced Accuracy；
- 每类 Precision、Recall、F1 和 Support；
- 混淆矩阵；
- PHONE_INTERACTION AUPRC；
- ECE、Brier Score、可靠性图；
- 拒识覆盖率与覆盖样本准确率；
- PyTorch 与 ONNX 数值差异。

关键对比必须使用相同 test 清单：

- V3.2 原始整图推理；
- V3.2 人物裁剪诊断；
- MobileNetV3 完整画面；
- MobileNetV3 人物 ROI；
- 可选 ROI + 全局上下文。

离线候选模型达到以下条件才算本阶段有效：

1. test Macro-F1 和 Balanced Accuracy 明显高于 V3.2 可比基线；
2. READ、WRITE 和 PHONE_INTERACTION 的每类指标没有被总体 Accuracy 掩盖；
3. PHONE_INTERACTION AUPRC 达到可用于后续前摄验证的水平；
4. ONNX 与 PyTorch Top-1 一致，概率误差在预设容差内；
5. 数据清单、配置、随机种子、checkpoint 选择规则和模型卡齐全。

由于本阶段跳过真机测试，即使离线指标达标，也只能输出“候选 ONNX”，不能宣称手机端精度已经提升，不能替换 V3.2 生产资产。

## 10. 测试策略

- 数据审计单元测试：合法/非法 YOLO 行、边界裁剪、负尺寸框、缺失配对、重复哈希；
- 标签映射单元测试：三个数据源的 ID 到统一标签映射；
- 分组测试：同一组不得跨 train/validation/test；
- 裁剪测试：输出非空、边界合法、尺寸一致；
- 预处理一致性测试：Python 与 Android 的 RGB、resize、normalize、NCHW 对齐；
- 训练烟雾测试：小样本完成前向、反向、保存与恢复；
- 导出测试：ONNX shape、dtype、输出类别和数值一致性；
- 回归评估：固定小型样本集检测标签顺序和预处理漂移。

## 11. 非目标与后续阶段

本阶段不做：

- 不用公开静态图伪装成正式时序训练集；
- 不训练 GRU/TCN、Transformer 或 Pose 融合；
- 不修改正式提醒文案和默认开关；
- 不删除或覆盖用户下载的数据；
- 不加载来源不明的 `.pt`/pickle 权重；
- 不声称模型能够判断学生主观上是否认真。

后续获得真实手机前摄连续视频后，按学生和会话隔离建立 4～8 秒片段，再比较 MobileNetV3 + 后处理窗口、GRU 和 TCN。完成真机延迟、功耗、温度、长时间稳定性与提醒回放评估后，才讨论替换 V3.2。
