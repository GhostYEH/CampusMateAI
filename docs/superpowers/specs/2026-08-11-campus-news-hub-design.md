# 校园资讯中心设计

## 目标

将首页“校园动态”的“查看更多”改为独立的校园资讯中心。页面让学生能快速浏览、检索、筛选、收藏和阅读校园新闻，同时复用现有 `CampusNews` 数据与新闻详情页。

## 范围

- 新增 `campus-news` 二级路由和 `CampusNewsScreen`。
- 首页“查看更多”跳转至 `campus-news`；首页卡片仍直接打开对应新闻详情。
- 页面提供搜索、分类筛选、排序、只看未读、收藏与刷新。
- 点击任何资讯卡片进入既有 `campus-news-detail/{newsId}` 页面。
- 收藏和已读状态由本地持久化保存；不新增服务端接口。

不包含活动报名、日历订阅、评论或分享等需要新业务接口的能力。

## 视觉与布局

遵循现有 Compose 设计系统：`Background` 页面底色、`Surface` 卡片、蓝紫 `Primary` 主色、18-24dp 圆角和 `CampusPageHeader`。

1. 顶部为返回按钮、标题“校园动态”、副标题（显示当前结果数量）与刷新按钮。
2. 紧接可搜索标题、来源和标签的搜索框；搜索为空时显示正常内容。
3. 横向单选分类 Chip：全部和来自当前新闻数据的分类。第二行提供“最新 / 重要”排序，以及“仅未读 / 全部”切换。
4. 有置顶新闻时，首条以焦点卡显示：分类色带、标题、摘要、来源、时间及未读点。
5. 其他新闻按“今天 / 本周更早 / 更早”分组，以紧凑卡片列表展示。卡片显示分类标签、标题、两行摘要、来源和发布时间；收藏按钮可直接切换。
6. 无匹配结果显示可清除搜索或筛选的空状态；加载失败显示重试状态。

## 数据与状态

`CampusNewsScreen` 订阅现有 `AppRepository.campusNews`，进入页面和点击刷新时调用 `refreshCampusNews()`。

- `CampusNewsHubState`（或等价的 ViewModel 内状态）保存搜索词、所选分类、排序、未读过滤和本地收藏/已读集合。
- 过滤顺序固定为：分类、未读、关键词；再按所选排序输出。
- 阅读新闻时先标为已读，再导航详情。收藏切换应立即反馈并写入 DataStore。
- 首页卡片不承担本页状态；两处都使用同一份新闻数据。

## 组件边界

- `CampusNewsScreen`：页面状态、刷新和导航协调。
- `CampusNewsToolbar`：标题、返回与刷新。
- `NewsSearchAndFilters`：搜索、分类、排序和未读控制。
- `FeaturedNewsCard` 与 `CampusNewsListItem`：呈现新闻、已读状态、收藏操作和打开详情。
- 纯 Kotlin 的 `CampusNewsFilter`：过滤、排序及日期分组，便于单元测试。
- 本地状态封装在 `CampusNewsPreferences`（DataStore），避免把 UI 偏好混入远程新闻仓库。

## 边界与失败处理

- 刷新失败时继续保留上次已加载内容，并在列表上方显示非阻断提示与“重试”操作。
- 缺少分类、标签、图片或时间时，使用安全的默认展示，不崩溃也不隐藏整条新闻。
- 搜索无结果时不显示空白列表，提供明确说明与重置动作。
- 详情不存在时维持现有详情页的错误处理。

## 验收与测试

- 首页“查看更多”进入资讯中心；每张卡都能打开正确的详情页。
- 搜索、分类、未读与排序能组合生效，并显示正确的结果数。
- 收藏、已读在重启后仍存在；刷新不会清除它们。
- 刷新失败、空数据和无匹配结果都有可用状态。
- 为 `CampusNewsFilter` 覆盖关键词匹配、分类、未读过滤、排序与分组的单元测试；为本地偏好层覆盖收藏/已读读写。

## 自检

- 无待定项：本页使用现有新闻模型与详情路由，不依赖新增后端。
- 功能范围与数据边界一致：活动报名等服务端能力明确排除。
- 交互优先级明确：列表浏览和详情阅读是主路径，收藏与未读为本地增强。
