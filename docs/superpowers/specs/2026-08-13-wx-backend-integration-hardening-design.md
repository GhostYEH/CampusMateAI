# 微信小程序前后端联调强化设计

## 目标

让微信小程序在关闭 Mock 模式后完整使用现有 FastAPI 后端，并保证登录、课程、通知、待办、首页统计和 AI 辅导员的请求路径、字段及状态管理一致。安卓端保持只读。

## 架构

- 保留 `CampusRepository` 作为页面唯一数据入口，页面不直接调用 `wx.request`。
- 增加后端 DTO 与映射函数，将 snake_case 后端字段转换为小程序展示模型。
- 真实模式禁止静默回退到 Mock 数据，避免演示数据掩盖联调故障。
- 请求层集中处理错误消息、401 刷新、刷新失败后的会话清理和登录重定向。
- Mock/真实模式切换必须使旧会话失效，重新完成对应模式登录。

## 数据流

1. 登录保存 access token、refresh token、用户资料和会话模式。
2. 页面通过异步仓库方法读取课程、通知和待办。
3. 401 时只刷新一次 token，然后重放原请求；刷新失败则清理会话并返回登录页。
4. 通知解析使用后端 `content` 字段，适配多任务响应并逐项保存。
5. AI 辅导员明确请求非流式 JSON，使用 `conversation_id` 维护会话。

## 错误处理

- 优先显示后端 `message` 或 `detail`，保留 HTTP 状态作为兜底。
- 保存、删除、完成等写操作必须等待服务器成功后才能提示成功。
- 真实模式加载失败显示空态/错误态，不混入本地演示数据。

## 验证

- 小程序源码契约测试锁定路由、请求字段、响应模式和鉴权生命周期。
- TypeScript、WXML 事件和安卓视觉契约检查继续执行。
- 后端全量 pytest 与 FastAPI TestClient 真实接口烟雾测试必须通过。
