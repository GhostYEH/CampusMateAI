# 正方教务系统全链路自动适配设计

## 背景

CampusMateAI 已具备教务网址探测、正方表单登录、客户端 WebView 登录、教务会话管理、课表同步与三端课表展示能力，但学校配置仍依赖预先写入的数据端点。河南财经政法大学的登录与身份端点已经验证，个人课表端点尚未配置，因此账号可以登录，课表同步必然在 `schedule_path` 缺失处失败。

本设计将学生填写的教务系统网址作为唯一可信入口，在不猜测学校网址、不绕过人机验证的前提下，自动识别多数正方版本的登录协议与个人课表协议，并以严格校验和原子提交保证错误数据不会覆盖已有课表。

## 目标

- 学生在 Web、Android 或 HarmonyOS 填写教务网址后，由后端识别正方版本和登录方式。
- 普通正方表单登录自动完成；图片验证码在 CampusMate 内由用户读取和填写。
- 滑块、短信、MFA、统一身份认证等流程转入受限 WebView，由用户本人完成验证。
- 登录成功后，从同源的已认证菜单和课表页面发现真实个人课表协议，不套用未经验证的通用功能编号。
- 支持正方常见 JSON、HTML 表格和嵌套响应，统一转换为现有 `EduSchedule` 契约。
- 任何不确定、空响应、结构突变或解析失败都采用 fail-closed：保留上一次成功课表，不写入猜测数据。
- 三端共享同一后端协议和同步状态，不在客户端复制学校网页解析逻辑。

## 非目标与安全边界

- 不根据大学名称、官网域名或历史经验猜测教务网址。
- 不破解或 OCR 自动识别验证码，不绕过滑块、短信、MFA、统一身份认证或学校访问控制。
- 不扫描任意站点路径，不执行从未认证页面、跨域页面或第三方脚本推断出的请求。
- 不修改数据库结构、公开课表模型格式或现有部署流程；协议缓存复用现有教务系统配置字段。
- 不将账号密码、Cookie、Token、验证码、完整网页或完整原始课表响应写入日志和持久化诊断信息。

## 总体架构

教务连接继续由后端统一负责，三端只提供输入、人工验证和状态展示：

```text
学生填写 HTTPS 教务网址
  -> SSRF 与精确 Origin 校验
  -> ProviderDetector 识别正方版本和登录模式
  -> 普通表单登录 / 图片验证码 / 受限 WebView
  -> 已登录身份端点校验学生身份
  -> ZhengfangCapabilityDiscoverer 发现个人课表协议
  -> 候选协议执行一次同源只读验证
  -> ZhengfangParser 严格解析与规范化
  -> EduScheduleValidator 校验批次完整性
  -> EduDataRepository 原子写入
  -> Web / Android / HarmonyOS 读取统一课表
```

静态已验证学校配置仍作为快速路径。配置缺失、失效或页面指纹变化时进入动态发现；动态发现成功后将最小协议描述缓存到对应教务系统配置，后续连接直接复用。

## 正方协议发现

### 输入与约束

发现器只接收以下输入：

- 已通过 SSRF 防护和 HTTPS 精确 Origin 校验的 `SchoolConfig`。
- 已通过学生身份端点验证的 `ZhengfangHttpClient` 会话。
- 已登录菜单或首页的响应内容。

发现器只允许访问：

- 与 `allowed_origin` 完全一致的 HTTPS 地址。
- 已登录菜单、页面标记、表单 action 或同源脚本明确引用的路径。
- 路径和语义同时符合个人课表查询的候选，例如菜单文本、正方功能标识、`xskbcx`/`xsKb` 等稳定协议特征。

### 候选协议

每个候选协议包含：

- 个人课表入口路径和数据路径。
- GET 或 POST 请求方式。
- 学年、学期及必要固定参数的字段名。
- JSON 或 HTML 响应格式。
- 来源页面路径、正方功能标识和结构指纹。
- 用于失效判断的页面或脚本指纹，不包含页面正文与个人数据。

候选来源按可信度排序：

1. 已验证学校静态配置。
2. 已登录菜单中明确标注“个人课表”的同源入口。
3. 个人课表页面表单和同源脚本明确引用的数据请求。
4. 与已确认版本匹配的内置正方策略模板，但仍必须经过真实响应验证。

仅凭常见路径或常见功能编号生成的候选不能直接持久化。

### 验证与缓存

候选协议必须满足以下全部条件才能升级为已验证配置：

- 请求保持在精确允许 Origin 内。
- 响应不是登录页、权限错误页、验证码页或通用首页。
- 响应格式可被严格解析器识别。
- 解析后的每条记录通过课程字段校验，且整体批次通过一致性校验。
- 学期参数与返回数据的学期信息不冲突。

验证成功后，只缓存请求路径、方法、参数映射、响应格式和结构指纹。若连续请求返回未登录、无权限、404、字段结构变化或指纹不匹配，则使缓存失效并重新发现一次；重新发现仍失败时返回明确错误，不继续枚举路径。

## 登录与人工验证

### 自动表单登录

保留现有正方 RSA 公钥、CSRF、Cookie 和表单字段流程。HTTP 客户端在同一登录事务内复用连接池和 Cookie jar，统一捕获 TLS、代理、连接重置和响应读取异常，映射为稳定的教务错误码。

对可安全重试的 GET 预登录、公钥和身份探测请求进行有限重试；登录 POST 默认不盲目重放。只有确认服务端未收到请求时才允许重试，避免重复认证行为。

### 图片验证码

后端获取同源验证码图片并绑定到一次性预登录会话。三端展示图片、允许刷新和输入，提交时同时发送预登录令牌、账号、密码和用户填写的验证码。预登录会话过期、验证码错误或刷新后，旧令牌立即失效。

### WebView 降级

滑块、短信、MFA、统一身份认证或无法安全自动化的流程进入 WebView。WebView 只能导航到后端返回的精确 HTTPS Origin 列表；客户端过滤外部 Scheme、非允许 Origin 和不安全 Cookie。用户完成登录后，客户端回传结构化 Cookie jar、当前 URL 和 User-Agent，后端再次访问身份端点确认真实学生身份后才建立教务会话。

## 课表解析与正确性

### 响应分类

解析前先分类响应：JSON、JSON 字符串包装、HTML 表格、登录页、权限错误、验证页或未知格式。登录页、权限错误和未知格式绝不作为空课表处理。

### 规范化

解析器将正方常见字段映射到现有 `EduScheduleItem`：课程名称、课程代码、教师、地点、星期、开始/结束节次、开始/结束时间、周次、学期、学分、课程性质、教学班和允许的扩展信息。

禁止通过模糊文本猜测关键字段。星期、节次和周次只有在格式明确时才转换；无法确定的关键字段使该记录无效。可选字段缺失不影响其他字段，但不得以默认值伪造成学校返回值。

### 批次校验

`EduScheduleValidator` 在写入前验证：

- 课程名称非空且不是错误提示或页面标题。
- 星期为 1 至 7，节次为正整数，结束节次不早于开始节次。
- 周次表达式可解析，且展开范围不冲突、不超出合理学期范围。
- 同一远端课程记录的规范化键稳定，重复项可幂等合并。
- 请求学期与响应学期不存在明确冲突。
- 响应宣称成功但解析记录全部无效时判定为失败。
- 空课表只有在响应明确表示该学期无课且结构有效时才可接受。

校验器返回成功、明确空课表或失败三态，并附带不含个人内容的错误阶段和计数。

## 原子同步与回滚

同步先在内存中完成抓取、解析、规范化和校验。只有批次通过后，仓库才在单一事务中：

1. 写入本次有效记录。
2. 标记当前学期旧记录的保留、更新或失效状态。
3. 更新同步记录、结构指纹和最后成功时间。
4. 提交事务。

任一步失败都回滚事务，已有课表和最后成功时间保持不变。同步失败记录可以写入失败阶段、错误码、候选数量和无敏感信息的结构摘要，但不能写入原始响应、课程正文、账号或会话信息。

## API 契约

现有端点保持兼容：

- `POST /edu/discovery/probe`
- `POST /edu/connections/from-url`
- `POST /edu/connections/{id}/pre-login`
- `POST /edu/connections/{id}/continue`
- `POST /edu/sync/schedule`
- `GET /edu/schedule/items`
- `GET /edu/sync/records`

连接和同步响应扩展可选字段，用于三端展示阶段：

- `stage`: `login`、`verification`、`identity`、`protocol_discovery`、`fetch`、`parse`、`validate`、`commit`。
- `previous_schedule_preserved`: 本次失败时是否保留旧课表。
- `requires_user_action`: `image_captcha`、`webview` 或空。
- `protocol_source`: `static_verified`、`cached_discovered`、`live_discovered`。

新增字段均为可选，旧客户端仍可按现有 `state`、`error_code` 和 `message` 工作。

## 三端交互

Web、Android 和 HarmonyOS 保留现有“填写网址、检测、登录并绑定”入口。普通表单、图片验证码和 WebView 降级统一由后端状态驱动。

同步界面依次显示协议识别、读取、校验和提交阶段。只有后端返回成功且正式课表查询可读时显示“同步成功”。失败时展示具体阶段，并在 `previous_schedule_preserved=true` 时明确说明旧课表未被覆盖。

三端不解析学校网页，不持久化教务密码，不在普通偏好设置中保存 Cookie。课表页面继续只读取统一 API 模型并过滤已标记为过期的记录。

HarmonyOS 实施同时修复当前阻塞构建的 API 24 兼容错误：使用当前 SDK 支持的图片选择枚举，并以 ArkTS/系统支持的字节解码方式替代不可用的 `TextDecoder`。与教务无关的视觉断言差异单独记录，不借本任务改变视觉设计。

## 测试策略

### 后端自动化测试

- 正方登录页、公钥、验证码和身份探测协议。
- 多种菜单标记、功能编号和页面脚本的候选发现。
- 同源限制、跨域候选、危险 Scheme、权限错误页和登录页拒绝。
- JSON、字符串包装 JSON、HTML 表格及嵌套列表解析。
- 星期、节次、周次、学期冲突、重复课程和明确空课表校验。
- 协议缓存命中、指纹失效和单次重新发现。
- 临时批次成功提交与各失败阶段的事务回滚。
- 失败后旧课表与最后成功时间保持不变。

所有外部响应样本必须脱敏，不包含姓名、学号、Cookie、Token 或真实课程正文。

### 客户端测试

- Web API 契约、阶段文案、验证码流程、WebView 降级状态和旧课表保留提示；运行全量测试与生产构建。
- Android Repository、ViewModel 状态转换、验证码敏感状态清理、WebView Origin 防护和课表同步协调器；使用仓库捆绑 JDK 21 运行单测与 Debug 构建。
- HarmonyOS Repository、连接控制器、登录安全、导航返回和同步状态；运行 Hvigor 单测与 HAP 构建。

### 真实验收

使用用户明确授权的账号，仅在运行时输入凭据，执行：教务网址探测、真实登录、身份匹配、个人课表协议发现、当前学期同步、正式课表读取和非空条目计数校验。输出只包含阶段、状态、条目数量和结构校验结果，不输出密码、Cookie、姓名或课程明细。

若当前环境没有 Android 或 HarmonyOS 设备，只能完成客户端单测和构建；真机 WebView、Cookie 回传及权限交互必须明确标记为未验证，不能以模拟或源码检查代替。

## 上线与失效策略

动态发现默认只对已识别为正方且已完成身份认证的连接启用。静态已验证配置优先，动态配置按源站隔离。发现失败不影响登录绑定，但课表同步返回可诊断错误并保留旧数据。

协议结构变化时自动失效缓存并最多重新发现一次，避免循环请求学校服务器。学校出现限流、维护或网络限制时返回可重试状态，由用户主动重试，不设置后台高频探测。

## 验收标准

- 河南财经政法大学真实账号可完成登录、身份匹配、个人课表协议发现和当前学期课表同步。
- 至少覆盖两类正方课表响应格式，并通过固定脱敏样本回归测试。
- 恶意跨域候选、权限错误、登录页、结构突变和无效课程批次全部被拒绝。
- 任一失败路径不会覆盖上一次成功课表。
- Web 与 Android 全量测试、生产或 Debug 构建成功。
- HarmonyOS 教务相关测试通过且 HAP 构建成功；无设备时如实保留真机验收项。
- Git 提交只包含本任务文件，不包含凭据、本机路径、构建产物或其他会话改动。
