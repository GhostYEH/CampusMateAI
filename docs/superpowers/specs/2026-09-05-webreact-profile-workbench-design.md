# WebReact 个人工作台重构设计

## 目标

重构 `webreact/` 的学生端个人中心，重点解决“可用空间很大但文字过小、入口同权重、首屏信息密度低”的问题。页面继续服务于大学生快速查看身份、学习状态和校园工具，不改变接口、路由或已有功能。

## 范围与非目标

- 仅修改 React 客户端 `webreact/`；Vue、Android、HarmonyOS、微信小程序不改。
- 覆盖个人中心的 `overview`、`tools`、`settings` 三个 tab，以及个人中心使用到的共享视觉样式。
- 保留资料加载、资料保存、复制学号、刷新、学习记录跳转、工具入口跳转和设置开关行为。
- 不新增后端字段、不调整公开 API、不改变路由地址，不引入新的 UI 依赖。

## 设计方向

将页面从“均匀卡片墙”改为“校园运营工作台”：深墨色正文提高可读性，纸面白承载内容，靛蓝只表达主动作与导航，薄荷绿/琥珀色表达状态与类别。减少浅色渐变和装饰性阴影，只保留个人身份横幅中的插画作为页面签名。

### 信息层级

1. 页面标题和当前用户身份是首屏第一层，标题约 32px，核心身份字段约 13–14px。
2. 课程数量、待办事项、本周学习、成长积分为第二层，数值约 24px，辅助文字不低于 12px。
3. `tools` tab 以“学习陪伴”为主入口，其余 7 个工具为次入口；主入口通过更大面积和明确行动按钮体现优先级。
4. 收藏、资料、申请、发布、学习记录、身份卡独立为“个人中心入口”，减少重复描述，使用更适合扫读的 3 列操作区。

## 布局

桌面端（宽度 >= 1200px）：

```text
┌──────────────────────────────────────────────────────────┐
│ 页面标题 / 用户身份                              刷新     │
├──────────────────────────────────────────────────────────┤
│ 头像 + 姓名 + 身份字段 │ 课程 │ 待办 │ 学习 │ 积分       │
├──────────────────────────────────────────────────────────┤
│ 资料编辑 │ 我的工具 │ 设置                                  │
├──────────────────────────────────────────────────────────┤
│ 主入口：学习陪伴（2列宽） │ 工具 2 │ 工具 3                │
│                          │ 工具 4 │ 工具 5                │
│ 工具 6 │ 工具 7 │ 工具 8                                  │
├──────────────────────────────────────────────────────────┤
│ 个人中心入口：收藏 │ 课程资料 │ 申请记录                  │
│                  我的发布 │ 学习记录 │ 身份卡              │
└──────────────────────────────────────────────────────────┘
```

平板端使用 2 列，手机端使用 1 列；主入口在移动端仍位于其他工具之前。横幅在窄屏中改为上下结构，避免插画遮挡姓名与身份字段。

## 组件与职责

- `ProfilePage`：加载 profile/dashboard/sessions，持有 tab、编辑表单与设置状态，负责导航和保存动作。
- `ProfileHero`：展示页面标题、用户身份和四项统计；只接收展示数据与刷新回调。
- `ProfileTabs`：渲染三个 tab，接收当前 tab 并通过回调切换。
- `ToolCard`：渲染单个工具入口，接收 label/detail/icon/tone/featured 和点击回调，使用 button 保证键盘可达。
- `ProfileSection`：渲染入口区标题与卡片网格，负责统一区块间距，不持有业务状态。

如现有代码规模允许，优先先在 `ProfilePage.jsx` 内提取这些纯展示组件，避免创建只使用一次的过度抽象；若组件提取导致样式/测试成本上升，则保留 JSX 组合但保持上述职责边界。

## 数据与交互

- 首次加载继续用 `Promise.all` 并行请求 profile、dashboard、study sessions。
- 加载失败保留现有错误条和“重试”；加载期间使用与新布局匹配的 skeleton，避免空白区域。
- 工具卡与个人入口继续调用 React Router 的 `navigate`，不修改目标路径。
- 资料编辑继续使用现有 `updateProfile`；保存中禁用提交按钮，成功后显示已有提示。
- 复制学号、设置开关和减少动态效果继续使用现有状态与 localStorage key。
- 所有纯图标按钮带 `aria-label`；卡片入口使用真实 `button`，不依赖可点击 div。

## 样式策略

- 以个人中心专用类名覆盖现有移植样式，避免修改 Vue 共用目录行为。
- 统一使用现有 CSS 变量和 4px 间距基线；正文/描述/辅助文字分别设定最小字号 16/13/12px（标签可保留 11px，但不承载关键信息）。
- 卡片高度由内容决定，工具入口使用 `min-height: 96px`；不使用大面积空白强行拉伸。
- 交互状态包含 hover、focus-visible、disabled；动画遵循 `prefers-reduced-motion` 和现有 `reduce-motion` 设置。

## 验证

- 静态测试：运行 `npm test`，重点覆盖现有 profile/settings/sidebar/route 合同测试。
- 构建：运行 `npm run build`。
- 浏览器检查：个人中心在 1440、1024、768、390 宽度下无横向溢出，标题和工具名称可读，入口可点击，刷新/编辑/复制/开关行为不回归。
- 仓库卫生：完成前检查 `git diff`、`git status`，确认只产生 `webreact/` 代码/样式和本设计文档变更，不触碰用户已有的其他端改动。
