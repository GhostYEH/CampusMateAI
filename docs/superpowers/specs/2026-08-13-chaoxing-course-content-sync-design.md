# 学习通课程内容完整同步设计

## 目标

在现有学习通课程、未完成作业和通知同步基础上，增加面向课程详情的只读内容中心。系统应尽可能完整地同步学习通当前账号可访问的课程元数据，并在 Web、Android、HarmonyOS 三端提供一致的信息结构。

文件资源只同步元数据。用户点击下载时，由后端携带该用户的学习通会话代理获取文件；首次成功获取后写入受控缓存，后续请求优先命中缓存。

## 范围

每门学习通课程尽量同步以下数据：

- 课程信息：课程名称、封面、学校、班级名称、教师、学生人数、开课与结课时间、学习通原始入口。
- 章节目录：多级章节、排序、任务点数量、已完成状态和原始入口。
- 课程内容：文档、课件、视频、音频、图片、链接、章节测验等可识别资源。
- 独立资料：课程资料区中可见的文件和文件夹元数据。
- 作业：标题、课程、状态、截止时间及学习通详情入口。
- 考试：标题、状态、开始与结束时间及学习通入口。
- 通知：标题、正文、发布者、发布时间和课程归属。
- 讨论：主题、发布者、发布时间、回复数和学习通入口。

同步和展示均为只读。提交作业、参加考试、发表评论、完成任务点、签到等会改变学习通状态的操作不在本期范围内，客户端应跳转学习通完成。

## 设计原则

1. 真实数据优先：只展示学习通实际返回的数据，不生成模拟章节、资源或统计。
2. 部分成功：任一栏目失败不得回滚已成功同步的其他栏目。
3. 可解释完整性：每个栏目记录同步状态、返回数量、同步时间和错误原因，空列表与同步失败必须区分。
4. 幂等同步：以用户、课程、内容类型和学习通稳定标识组成唯一键；重复同步只更新内容，不产生副本。
5. 安全下载：后端不向客户端暴露学习通 Cookie，不允许客户端传入任意下载 URL。
6. 三端一致：三端使用同一后端接口和字段语义，同时遵循各端现有视觉与导航习惯。

## 后端架构

### 课程远程信息

扩展 `courses` 表，增加以下可空字段：

- `remote_class_id`
- `remote_cpi`
- `remote_school_name`
- `remote_class_name`
- `remote_student_count`
- `cover_url`
- `starts_at`
- `ends_at`

这些字段来自课程列表接口，是后续访问章节和内容接口所需的基础上下文。

### 统一课程内容项

新增 `course_content_items` 表，表示课程内所有可浏览内容。核心字段：

- `id`：本地标识。
- `user_id`、`course_id`：数据所有者及本地课程。
- `provider`：固定为 `chaoxing`。
- `external_id`：学习通稳定标识。
- `parent_external_id`：章节树父节点标识。
- `kind`：`chapter`、`document`、`video`、`audio`、`image`、`link`、`quiz`、`material`、`exam`、`discussion`。
- `title`、`description`、`author_name`。
- `position`、`depth`：顺序和层级。
- `status`：如 `not_started`、`in_progress`、`completed`、`pending`、`closed`、`unknown`。
- `starts_at`、`deadline`、`published_at`。
- `mime_type`、`file_size`、`remote_object_id`。
- `source_url`：受控的学习通详情或下载源地址，仅服务端使用。
- `metadata_json`：保存类型特有但无需单独查询的原始字段。
- `last_synced_at`、`created_at`、`updated_at`。

唯一约束为 `(user_id, provider, course_id, kind, external_id)`。所有查询都必须包含 `user_id`，避免不同账号之间的数据串联。

### 栏目同步状态

新增 `course_sync_sections` 表，按课程保存 `overview`、`chapters`、`materials`、`assignments`、`exams`、`notices`、`discussions` 的状态：

- `status`：`complete`、`partial`、`unavailable`、`failed`。
- `item_count`
- `last_synced_at`
- `error_code`
- `error_message`

客户端据此展示“暂无内容”或“本次未同步成功”。

### 文件缓存

新增 `course_resource_cache` 表：

- 关联课程内容项和用户。
- 保存缓存相对路径、内容哈希、实际 MIME 类型、文件大小、写入时间、最后访问时间和过期时间。
- 相同内容哈希可复用磁盘文件，但授权仍按用户和课程校验。

缓存文件写入配置目录下的专用子目录，不使用学习通文件名作为磁盘路径。默认采用最近最少使用策略清理；缓存大小上限和单文件大小上限由配置控制。缓存记录缺失、文件损坏或过期时重新代理下载。

## 学习通数据获取

`ChaoxingClient` 拆分为按栏目获取的方法，统一接收课程上下文：`course_id`、`clazz_id`、`cpi`。

- 课程列表沿用 `mycourse/backclazzdata`，补充解析封面、学校、班级、人数、时间和 `cpi`。
- 章节优先使用当前可访问的 `gas/clazz` 与 `gas/knowledge` 数据，必要时回退到学生课程中间页解析。
- 章节卡片通过 `knowledge/cards` 获取，解析其中可见的资源元数据；不发送学习进度上报。
- 作业和通知沿用已验证的全账号数据源，再按课程归属映射。
- 考试、资料和讨论使用登录态可访问的数据源；当租户未开放或页面结构变化时，将栏目状态记为 `unavailable` 或 `failed`，不返回伪造空数据。

解析器必须与网络请求分离。每种真实响应保留脱敏测试夹具，测试解析结果、稳定 ID、层级关系、状态和资源下载标识。

## 同步流程

1. 验证学习通会话。
2. 获取课程列表并更新课程远程上下文。
3. 对每门课程逐栏目同步；栏目可有限并发，但同一账号设置并发上限以降低风控风险。
4. 每个栏目在独立事务中幂等写入内容项并更新栏目状态。
5. 成功完整获取的栏目可将本次已不存在的旧内容标记为 `stale`；失败栏目不得删除旧数据。
6. 返回总体统计及每门课程、每个栏目的状态。

同步接口仍保留完整同步入口，并增加单课程刷新接口。自动同步默认刷新课程、未完成作业、通知和轻量元数据；章节卡片等高请求量内容在首次打开课程或用户主动刷新时同步，之后按更新时间增量刷新。

## API

- `GET /api/v1/courses/{course_id}/content-summary`
  - 返回课程扩展信息、各栏目数量、同步状态和更新时间。
- `GET /api/v1/courses/{course_id}/content?kind=&parent_id=&page=&page_size=`
  - 返回章节树节点或指定类型的分页内容。
- `POST /api/v1/courses/{course_id}/sync`
  - 刷新单门课程全部只读内容，返回逐栏目结果。
- `GET /api/v1/courses/{course_id}/resources/{item_id}/download`
  - 校验账号、课程和资源归属后，从缓存或学习通代理返回文件。
- `GET /api/v1/courses/{course_id}/resources/{item_id}/open`
  - 对非文件内容返回受控跳转地址；需要修改状态的功能始终跳转学习通。

列表接口不返回远程 Cookie、签名参数或任意可由客户端篡改的下载 URL。

## 下载代理安全

- 资源必须先存在于本地元数据表，客户端只提交本地 `item_id`。
- 下载源主机必须属于明确允许的学习通域名集合，并禁止重定向到非允许域名。
- 每次下载重新校验当前用户拥有对应学习通课程且会话有效。
- 流式读取并执行单文件大小上限，避免将完整大文件载入内存。
- 使用服务端生成的安全文件名和正确的 `Content-Disposition`。
- 对上游 401、403、404、超限和网络错误返回稳定错误码，三端显示可操作提示。

## 三端产品设计

### Web

沿用现有 `StudentCourseDetailView` 的头部、标签和卡片风格，不重做视觉体系。

- 概览：显示封面、教师、学校、班级、章节/资料/作业/考试数量和各栏目同步状态。
- 章节：可展开多级目录，资源以图标和状态显示；点击文件下载，点击视频、测验等打开学习通。
- 资料：按文件夹或来源章节筛选，展示类型、大小、更新时间和缓存状态。
- 作业、考试、通知、讨论：显示只读列表及状态，操作按钮使用“在学习通查看”。
- 页头增加“刷新本课程”，显示逐栏目结果。

### Android

课程列表项点击进入新的原生课程详情目的地。详情采用现有 Compose 组件和颜色、间距规范：

- 顶部课程信息卡。
- 横向滚动栏目切换。
- 章节使用可展开列表。
- 下载通过系统下载/文件打开能力消费后端代理地址。
- 外部操作通过受控浏览器或学习通应用打开。

### HarmonyOS

课程列表项进入新的 ArkUI 课程详情页面，栏目、字段和空/错状态与 Android 保持一致：

- 使用现有 `SecondaryHeader` 和卡片组件。
- 章节采用折叠列表。
- 文件下载调用系统网络与文件能力，来源为后端代理接口。
- 学习通操作使用系统 URI 跳转。

## 错误与状态呈现

- `complete`：显示内容数量和最近同步时间。
- `partial`：显示已获取内容，并提示部分数据未取回。
- `unavailable`：说明当前课程或学校未开放该栏目。
- `failed`：保留旧数据并显示重试入口。
- 学习通会话过期：所有远程操作提示重新连接，已同步元数据仍可浏览，已缓存文件仍需通过本地授权校验后打开。

三端不得把网络失败、权限不足和真实空列表统一显示为“暂无内容”。

## 测试与验收

### 后端

- 使用真实响应结构的脱敏夹具覆盖课程扩展信息、章节树、卡片资源、资料、考试和讨论解析。
- 验证重复同步不产生副本，失败栏目不删除旧数据，不同用户数据隔离。
- 验证下载代理的课程权限、域名白名单、重定向限制、大小限制、缓存命中和缓存损坏恢复。
- 对真实已绑定账号执行一次只读同步审计，核对上游计数、数据库计数和 API 计数。

### 三端

- Web 生产构建通过，并验证桌面和窄屏课程详情。
- Android 编译和课程详情状态测试通过。
- HarmonyOS 编译或项目现有静态检查通过。
- 三端针对 `complete`、真实空列表、`partial`、`failed` 和会话过期显示一致语义。

## 验收标准

1. 三端均可从课程列表进入课程详情，且栏目位置合理、语义一致。
2. 真实学习通账号可看到同步到的课程章节与可识别资源，不展示模拟内容。
3. 每类数据的同步成功、失败和真实为空可以区分。
4. 文件首次点击经后端代理下载，后续可命中本地缓存；客户端永远拿不到学习通 Cookie。
5. 用户无法通过修改请求下载其他课程、其他用户或非学习通域名的内容。
6. 提交、考试、评论等写操作不会由本软件代为执行。

## 非目标

- 自动完成课程任务点或伪造学习进度。
- 自动提交作业、参加考试、签到或发帖。
- 绕过学习通权限、验证码、学校限制或资源访问控制。
- 一次性永久下载全部课程文件。
- 保证学习通未向当前账号开放的数据也能被获取。
