# CampusMate AI 真机测试清单

> 本文档包含具体的真机操作步骤，每步均需在真实 Android 设备上验证。

## 前置准备

1. Backend 已启动（`start_backend.bat` 或 `python -m uvicorn app.main:app`）
2. Web 已启动（`start_web.bat` 或 `npm run dev`）
3. Android Debug APK 已安装到真机
4. 真机已安装微信和学习通
5. 真机已登录学生账号（student_demo / Demo123456）

## 一、微信通知捕获

### 1.1 正常校园通知

1. 安装 Debug APK
2. 登录 Student（student_demo / Demo123456）
3. 设置 → 通知访问权限 → 开启 CampusMate
4. 从另一微信账号向学生微信发送：`数据结构实验三周五23:59前提交到学习通`
5. 打开 CampusMate → 通知中心
6. 验证通知出现
7. 验证来源显示"微信"
8. 点击通知 → 解析
9. 验证 deadline 显示为本周五 23:59
10. 保存为待办
11. 验证任务页出现该待办

### 1.2 普通聊天过滤

1. 从微信发送：`晚上吃什么？`
2. 打开 CampusMate → 通知中心
3. 验证该消息未出现在通知列表中（已过滤）

### 1.3 重复通知去重

1. 从微信发送：`请2024级学生于7月30日前提交实践申请表至教务处`
2. 再次发送完全相同的内容
3. 打开 CampusMate → 通知中心
4. 验证只有一条通知（去重生效）
5. 验证任务页只有一个对应待办

### 1.4 撤销权限

1. 设置 → 通知访问权限 → 关闭 CampusMate
2. 返回 CampusMate → 个人设置 → 通知设置
3. 验证显示"通知使用权未开启"
4. 验证 App 不崩溃
5. 验证通知列表显示空状态或已有通知

### 1.5 App 后台

1. 开启通知权限
2. 从微信发送校园通知
3. 将 CampusMate 切到后台
4. 再切回前台
5. 验证通知已捕获并显示

### 1.6 Backend 断开

1. 停止 Backend 服务
2. 从微信发送校园通知
3. 打开 CampusMate → 通知中心
4. 验证通知仍保存本地
5. 点击 AI 解析
6. 验证显示"AI 服务暂时不可用"提示，不崩溃
7. 重启 Backend
8. 再次点击解析
9. 验证可正常解析

## 二、学习通通知

1. 设置 → 通知访问权限 → 确认已开启
2. 从学习通发送通知（如作业截止提醒）
3. 打开 CampusMate → 通知中心
4. 验证通知出现
5. 验证来源显示"学习通"
6. 点击解析 → 保存待办
7. 验证任务页出现该待办

## 三、AI 校园助手（RAG）

### 3.1 有知识库回答

1. 确认 Backend 已导入 Demo 知识库
2. 打开 CampusMate → AI 校园助手
3. 输入：`奖学金申请需要哪些材料？`
4. 验证返回回答
5. 验证回答中包含引用来源（如"学生奖学金申请说明"）
6. 验证不显示内部 document_id

### 3.2 无知识库回答

1. 输入：`学校允许带宠物进入宿舍吗？`
2. 验证回答提示"知识库暂未检索到相关资料"或类似表述
3. 验证不凭空编造校园政策

## 四、CameraX 专注模式

### 4.1 正常使用

1. 打开 CampusMate → 学习陪伴 → 专注模式
2. 授予摄像头权限
3. 验证摄像头预览正常显示
4. 验证表情识别与学习状态辅助正常工作：`VISIBLE_STUDY` 只表示检测到明确学习动作，`IDLE` 只表示暂未观察到明确动作
5. 验证 Presence 可显示 `PRESENT` / `OBSERVING` / `ABSENT`，且 `PRESENT + IDLE` 可同时出现
6. 退出专注模式
7. 验证摄像头正常释放

### 4.2 Presence 与共享 CameraX 验证

1. 正脸进入 Focus，验证 ML Kit 人脸或 person evidence 出现后 Presence 为 `PRESENT`
2. 长时间侧脸或低头，验证 person detector 仍能作为在席证据；不要期待人脸检测始终成功
3. 在 `PRESENT` 后短暂遮挡或调整姿势少于 12 秒，验证不会立刻切到 `ABSENT`
4. 连续至少 12 秒没有 person、人脸和稳定行为 evidence，验证才进入 `ABSENT`
5. 恢复任一正向 evidence，验证立即回到 `PRESENT`
6. 重复进入退出，验证没有第二条摄像头或“Camera already in use”错误

### 4.3 权限拒绝

1. 拒绝摄像头权限
2. 打开专注模式
3. 验证显示权限提示，不崩溃

### 4.4 后台/前台切换

1. 进入专注模式
2. 切到后台
3. 验证摄像头合理暂停
4. 切回前台
5. 验证摄像头合理恢复

### 4.5 Debug 本地视觉测试（仅 Debug）

1. 在 Focus 的摄像头构图提示下展开“开发者工具”
2. 进入“本地视觉测试”，断开后端后仍验证 CameraX、V3.2-A、表情、Presence 和 Debug 采集可用
3. 确认页面明确显示 Debug 本地视觉测试，且不会创建或上传正式 Focus session
4. 若采集数据，选择 `idle`、`visible_study` 或 `visible_study_hard`，等待 5 秒倒计时后检查才开始保存
5. 验证采样约为 1 FPS、单 session 最多 120 张，并在停止后不再继续保存

### 4.6 重复进入退出

1. 进入专注模式
2. 退出
3. 再次进入
4. 再次退出
5. 验证无"Camera already in use"错误
6. 验证无 Surface 泄漏

## 五、管理员 Web 后台

### 5.1 管理员登录

1. 打开 Web → 登录页
2. 使用 admin_demo / Demo123456 登录
3. 验证跳转到 /admin
4. 验证显示管理员仪表盘

### 5.2 知识库管理

1. 进入 /admin/knowledge
2. 点击上传文件
3. 选择一个 .md 文件
4. 验证上传成功，列表刷新
5. 删除刚上传的文档
6. 验证删除成功，列表刷新
7. 点击重建索引
8. 验证重建成功

### 5.3 学生无法进入

1. 退出管理员
2. 使用 student_demo / Demo123456 登录
3. 手动访问 /admin
4. 验证被重定向到 /home

## 六、微信小程序

1. 打开微信开发者工具
2. 加载 wx/ 项目
3. 编译运行
4. 验证首页正常显示
5. 验证 Tab 栏显示"AI 校园助手"（非"AI 导员"）
6. 进入 AI 校园助手页面
7. 发送消息
8. 验证返回回答（Mock 或真实后端）
