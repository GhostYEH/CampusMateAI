## 五、移植时怎么找对应文件

1. **先看类名。** 本仓库移植层的类名与参考**逐字一致**，所以
   `grep -r "某个类名" <参考项目>\components` 能直接定位来源（路径见 README 的 `$REF`）。
2. **看移植层文件头的注释。** `webreact/src/maic/**` 每个文件头部都写了
   "逐字移植自参考 `xxx/yyy.tsx`（第 N-M 行）"，并列出机械改写清单。
3. **`_compat/` 目录是替代品清单。** `webreact/src/maic/slide/_compat/` 与
   `scene/lib/` 里每个文件头都注明了它替代了参考的哪个模块、为什么。
4. **注意版本差异。** 参考项目的 `package.json` 是 `1.0.1`，而仓库固定的来源是
   `v1.0.3`（见 `third_party/openmaic/UPSTREAM.json`）。逐文件比对结论在
   `third_party/openmaic/` 的清单里；`packages/@openmaic/dsl/src/**` 是逐字节一致的。

## 六、机器上的额外副本（**不是来源**）

开发机上可能还有一份参考项目的运行副本（含 `node_modules`、`.next`、本地凭据）。
它**不是 provenance**，不能被引用，也**不要把它的路径写进仓库文件**。
`docs/openmaic-deployment.md` 里有完整的边界说明。

启动它做比对是可以的（`npx next dev -p 3300`），但**用完要关掉**——
它会占用大量内存，而这台机器有 WHEA 硬件报错史。
