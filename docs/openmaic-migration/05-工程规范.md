## 测试怎么写（照抄仓库现有风格）

### 前端：`webreact/tests/*.test.mjs`，`node --test`

这个仓库大量使用**源码级契约测试**：`read()` 出组件源码，用 `assert.match` 钉住
"必须长这样"，以及 `assert.doesNotMatch` 钉住"不得退回旧写法"。

```js
const read = (rel) => readFileSync(fileURLToPath(new URL(`../${rel}`, import.meta.url)), "utf8");
const stageSource = read("src/components/openmaic/OpenMAICClassroomStage.jsx");

test("...", () => {
  assert.match(stageSource, /api\.runOpenMAICDiscussion\(/, "必须走真实讨论接口");
  assert.doesNotMatch(stageSource, /sandbox="[^"]*allow-same-origin/, "不得放宽沙箱");
});
```

**但必须清楚它的局限**：源码级断言挡不住逻辑错误。圆桌那次我写了
"必须轮询 job" 的断言、测试是绿的，真跑浏览器才发现判据写反了（详见 `04-陷阱.md` 第 6 条）。
**关键链路一定要真跑。**

### 受管服务：`openmaic-service/tests/*.test.mjs`

`node --experimental-strip-types --test`，可以直接 `import` `.ts`。
纯函数优先——合成器、投影、判别子都是纯函数，把几何不变量与边界钉在这里，
**不要**引入模型调用。

### 后端：`backend/tests/test_*.py`，pytest

改了 `openmaic-service` 的读写路径或网关契约就要跑。

## 浏览器验收的硬要求

1. **必须真跑，不许 mock 后端。** 用 `backend\.venv\Scripts\python.exe` 跑 Playwright。
2. 每个切片都要**截图**，并收集 `pageerror` / `console error` / `>=400` 的 API 响应。
3. 结论里报**具体数字**（"pageerror 0 条"），不要写"没发现问题"。
4. **窄屏至少验 320px。** 这个宽度历史上出过两次真实缺陷：
   - 侧栏固定占 220px，把主列压成 100px；
   - 头栏右控制簇盖住「返回按钮」并吃掉点击
     （只有用 `document.elementFromPoint` 才能查到，肉眼看不出）。
5. 一次性验收脚本**用完就删**，不要留在仓库里。

## 提交规范

- **一个切片一次提交。**
- 提交信息**聚焦 why**（为什么这么改），用**中文**。仓库现有提交可作范本。
- **只暂存本次任务相关的文件。** 工作区里可能有别处遗留的改动
  （例如 ` M .gitignore`、`?? backend/data/banner_images/`），**不要一起提交**。
- 提交前跑：`git diff`、`git diff --cached`、`git status`，确认
  没有密钥、没有本机绝对路径进入变更。
- **不要提交**：截图、日志、临时脚本、构建产物、`.env`。

## 交付说明必须包含（每个切片）

1. 改了哪些文件（路径）。
2. **参考实现的哪个文件、哪一段**被对齐（给出参考侧路径与行号范围）。
3. 与参考**有意不同**的地方，以及为什么。
   "没有对应运行时"是正当理由；"顺手简化了"不是。
4. 验证证据：
   - 单测通过数、构建结果；
   - **真实浏览器**的几何 / 文本实测值；
   - pageerror 与 console error 的**具体条数**。
5. 还没做完的部分，明确说出来。

## 文档维护

`docs/openmaic-capability-matrix.md` 是能力矩阵，**新增或改变一项能力时要同步更新**。
它要求每行都有：源码依据、CampusMate 文件、契约、权限、测试文件、验收命令、证据。
状态只有"部分完成 / 已验证"两档；**没有浏览器证据就不能写"已验证"**。
