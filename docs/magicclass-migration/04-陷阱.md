# 04 · 陷阱：已经踩过的坑

**动手前必读。** 每一条都是真踩过的，照做能省几小时。带 ⚠️ 的是"看起来像前端坏了、
其实不是"这类最容易误判的。

---

## ⚠️ 1. 含 JSX 的文件必须是 `.jsx`，不能是 `.js`

Vite 的模块分析会对 `.js` 里的 JSX 直接报：

```
Failed to parse source for import analysis because the content contains invalid JS syntax.
If you are using JSX, make sure to name the file with the .jsx or .tsx extension.
```

**想保留 `index.js` 这个导入路径**（推荐），就让 `index.js` 只做再导出，
实现放进 `index.jsx`。已有先例：`src/maic/classroom/index.js` → `shell.jsx`、
`src/maic/scene/index.js` → `scene-renderer.jsx`。

判断某个 `.js` 是否含 JSX 的可靠办法：用 esbuild 以 `loader: "js"` 试解析，
报 `JSX syntax extension is not currently enabled` 的就是。

## ⚠️ 2. 不要给 Playwright 同时加 `--disable-gpu` 和 `--disable-software-rasterizer`

两个一起加 = 没有任何光栅化器 = **页面完全不绘制** → 元素没有 bounding box →
Playwright 判定"不可见" → **连登录都登不进去**。

而报错是"等待 `input[autocomplete="username"]` 超时"，极容易被误判成"前端坏了"。
**只加 `--disable-gpu` 就好。**

（本机有 WHEA 硬件报错史，降 GPU 负载是合理的；但别顺手把软件光栅化也关了。）

## 3. `.maic-root` 作用域必须由承载方提供

Tailwind 令牌与工具类**只**在 `.maic-root` 内生效。移植组件本身**不**带这个类
（为了类名与参考逐字一致），所以集成层要自己加。

## 4. 绝对不要引入 Tailwind 的 preflight

`src/styles/maic.css` 只 `@import "tailwindcss/theme.css"` 与
`tailwindcss/utilities.css`。加 `@import "tailwindcss"` 会带进 preflight，
全局重置 margin/padding/边框，把站内所有手写 CSS 的页面一起改掉。
已有测试钉住这一点。

## 5. 参考项目播放态的工具栏是"并入"圆桌的，不是被丢弃

`canvas-area.tsx` 在播放态传 `hideToolbar={mode === 'playback'}`，一开始看像是
"播放时没有工具栏"。但 `components/roundtable/index.tsx` 里写着
`Toolbar strip — merged from CanvasArea`。

底部实际是「工具栏条 36px **并入圆桌** + 三栏交互区 156px」共 192px。
**别把工具栏和圆桌叠成两条。**

## ⚠️ 6. 任务型接口会同时回 `job_id` 和一个 `job` 快照

`POST /discussion`、生成类接口都会回：

```json
{ "job_id": "job_xxx", "job": { "id": "job_xxx", "status": "queued", ... } }
```

轮询判据**必须**是 `job?.status !== "completed" && started?.job_id`。

用 `!job` 判断会拿到一个 `queued` 快照就径直按失败处理 —— 表现为
"点了开始讨论，永远没有结果"。**这个 bug 只有真跑浏览器才能发现**：
源码级断言是绿的，模型单测也是绿的。

正确写法可参照 `webreact/src/components/magicclass/ProviderToolsPanel.jsx` 的 `submit()`。

## 7. 读取时投影必须是确定性的

投影靠"内容没变就不重写"来避免触碰存量数据库字节。一旦合成里出现
`new Date()` 或随机数，每次读取都会"变了"，幂等判断与"没变就不重新序列化"永久失效。

参考项目自己的 `upgradeLegacyPBLConfigToProjectV2` 会注入时间戳——那是可以的，
因为它只用于单向展示；**我们的投影不行**。渲染器本身会补 `updatedAt`。

## 8. 改服务端读取路径要跑后端测试

`magicclass-service/src/workspace/repository.ts` 的 `getStage` 是**所有读路径的唯一咽喉**：
编辑、播放、导出、归档、渲染全都经过它。改它会同时影响这五条链路。

## 9. 参考项目是只读的

- 不要修改 `$REF`（参考项目，路径见 README）。
- **不要**把它的大体积二进制资源（如 `public/logo-horizontal.png`）拷进仓库——
  那要走 `third_party/magicclass/` 的 LICENSE / NOTICE / SHA 清单流程。
  缺图就用文字字标替代，**别留破图**。
- **不要把它的绝对路径写进任何提交物**（现有的 `02-现状.md` 在内部文档里提到它是
  为了交接，源码与配置里不得出现）。

## 10. `.env` 里有真实密钥

已被 gitignore。不要写进任何提交物、日志、测试夹具或截图。
`backend/.env` 与 `magicclass-service/.env` 两侧的 `MAGICCLASS_INTERNAL_SECRET` 必须一致，
不一致会表现为每次调用都被断言拒绝（`state=unavailable`、`reason=assertion_rejected`）。

## ⚠️ 11. PowerShell 不展开通配符

`pytest tests/test_magicclass_*.py` 会**收集到 0 个用例**并报 `no tests collected`——
照抄会以为测试通过了。正确写法：

```powershell
.\.venv\Scripts\python.exe -m pytest tests -k magicclass -q      # 370 个用例
```

同类坑：本机若设了 HTTP 代理，访问 `127.0.0.1` 的脚本可能被代理接管。
跑真实浏览器 / 真实 HTTP 前先设 `$env:NO_PROXY='127.0.0.1,localhost'`。

## ⚠️ 12. PowerShell 把路径里的 `[` `]` 当通配符

参考项目里有 `app/classroom/[id]/page.tsx` 这类方括号目录。用 `Get-Item` / `Get-Content`
按普通路径读它，PowerShell 会把 `[id]` 当成字符类，**解析到别的路径或读成 0 字节**——
不报错，只是静默给出错误结果。

本目录的初稿就因此写错了一句"这个文件是空的"，实际它有 318 行。

**对策**：读这类路径一律加 `-LiteralPath`：

```powershell
# <参考项目> 用实际路径替换（见 README 的 $REF 说明）
Get-Item -LiteralPath '<参考项目>\app\classroom\[id]\page.tsx'      # 正确
Get-Content -LiteralPath '<参考项目>\app\classroom\[id]\page.tsx'   # 正确
```

或者直接用支持字面路径的读取工具。**凡是"文件是空的/不存在"的结论，
先用 `-LiteralPath` 复核一遍再下。**

## ⚠️ 13. `magicclass-local.mjs start` 是全有或全无，端口被占时会"跑一下就退出"

任一端口被占（最容易被占的是 `:4010`，因为这个仓库可能同时有别的会话在跑受管服务），
对应子进程会退出，启动器随即把另外两个也一起关掉。

**表现**：命令跑了一下就结束、退出码 1，而日志里只有 Vite 的 HMR 输出，看不到明显报错——
很容易被误判成"代码坏了"。

**对策**：先 `node scripts/magicclass-local.mjs doctor`，看「端口占用」一节。
若 `:4010` 已被一个健康实例占住，就**只起缺的那两个**（Vite / FastAPI），别反复重试 `start`。
完整命令见 `README.md` 的「快速开始」。

另一个容易误判的点：`http://127.0.0.1:4010/` **一定返回 404**，因为受管服务只暴露
`/internal/*`。判断它是否在跑要用 `/internal/health/live`，不是根路径。

## 附：本机特有的两个坑

### A. 登录页有入场动画会重渲染，`fill()` 可能反复失败

稳妥顺序：`goto(domcontentloaded)` → `wait_for_selector(input)` → `wait_for_timeout(6000)`
→ 才 `fill`，并把 `fill` 的超时放宽。

选择器：`input[autocomplete="username"]` / `input[autocomplete="current-password"]` /
`button.login-submit`。演示账号 `student_demo / Demo123456`。

### B. 这台机器有硬件报错史

Windows 事件日志里有 `0x124 WHEA_UNCORRECTABLE_ERROR`（硬件级）与 `0x7E`
SYSTEM_THREAD_EXCEPTION_NOT_HANDLED。用户态进程产生不了 `0x124`。
若再次蓝屏，先看 `%SystemRoot%\Minidump\` 里的转储，别急着怀疑代码。
