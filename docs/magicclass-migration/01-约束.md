# 01 · 架构边界与红线

**动手前必读。** 这里的每一条都有测试或文档钉住，违反了轻则返工，重则破坏已有特性。

## 链路是固定的

```
浏览器 (webreact, Vite :5174)
   │ 同源 /api 反代
   ▼
FastAPI 网关 (:8000)      身份 / 课程 / 作业 / 资料 / 权限 / 上下文 / 审计 / 断言
   │ 短时 user + course + scope 断言（共享密钥）
   ▼
magicclass-service (:4010)  DSL / 编辑器 / 播放器 / 导入导出 / 受限 Provider
```

### 红线 1：浏览器不得直连受管服务

`webreact/src/**` 里**不得出现**：

- `127.0.0.1:4010` / `localhost:4010`
- `MAGICCLASS_INTERNAL_SECRET`
- 任何绕过 FastAPI 直接打受管服务的代码

已有测试钉住：
`webreact/tests/magicclass-classroom-stage.test.mjs` →
`"the ported layer cannot reach the managed service directly"`。

### 红线 2：单一登录、单一课程权限

- 不引入第二套账号体系。
- 不引入第二套顶部/侧边导航。
- 不引入第二套课程库。
- 课程可见性只由 CampusMate 的课程权限决定。

受管服务**不提供公开首页**，也不提供登录页。

### 红线 3：iframe 只用于内容，不用于外壳

**唯一**允许 iframe 的范围是：互动 HTML、3D、模拟、游戏内容本身。

- 必须用**最小 `sandbox`**，且**不得**同时出现 `allow-scripts` 与 `allow-same-origin`。
- 是否允许 iframe 由**服务端的 `render.kind`** 决定，前端不放大权限。
- 不得把首页、工作台、编辑器、播放器整体放进 iframe。

判据在 `webreact/src/features/magicclass/playerModel.js` 的 `sandboxPolicyFor`；
`MagicClassClassroomStage` 复用它，且**不在组件里重建 sandbox 串**。

红线 3 说的是**内容型** iframe。承载**另一个完整应用**的跨源内嵌是另一条路径，
判据在 `webreact/src/components/interactive/ClassroomEmbed.jsx`：它要求跨源 +
`URL.origin` 精确白名单，`allow-same-origin` 仅在跨源成立时保留（Next.js 应用需要
自身 origin 的 storage），同源硬断言保证这一点。两条路径各有各的判据，不互相顶替。

## 例外：导航栏「学习空间」

「学习空间」是导航栏里的一个入口，指向**上游 magic class 应用本身**（仓库根目录
`magicclass-app/`，上游 v1.0.3 加一层可重放的品牌补丁），由 `LearningSpacePage` 跨源内嵌。这是
**唯一**一处经产品决策放宽红线 2 的地方，边界如下：

1. **独立进程、独立 Origin。** 上游应用跑在自己的进程与端口上（本地默认 `:3000`），
   CampusMate **不为它做反向代理**，也不把它的路由挂进本站路由表。
2. **不并入本站身份。** 它有自己的账号门禁与主题，CampusMate 的登录态、课程权限、
   审计都不流经它；反过来它的账号也不进 CampusMate。因此这不是"第二套账号体系
   进入本站"，而是"本站链接到另一个站点"——链路里没有任何一处让两者互相授权。
3. **仍走唯一的 iframe 渲染点。** 不新开 iframe，sandbox 不放宽，公开 Origin 未配置时
   fail-closed（`embed_origin` 为 null 就不渲染，不猜地址）。
4. **导航栏仍只有一套。** 加的是 `navItems` 里的一项，不是第二条导航；本站的
   顶部/侧边/悬浮导航实现没有第二份。
5. **上游源码只允许品牌补丁。** `magicclass-app/` 入库的是上游 `v1.0.3`，允许的偏离只有
   `scripts/magicclass-brand.mjs` 里定义的那一层（用户可见品牌词 `magic class`、npm 身份
   `@magicclass/*`）。校验方式是把补丁**逆向**还原后逐文件比对
   `third_party/magicclass/source-manifest.sha256`：`node scripts/magicclass-brand.mjs verify`。
   因此清单仍然钉住上游字节，任何补丁之外的改动都会被指出来。需要同样的行为时改本站
   （`.env`、网关、前端），不要往上游源码里塞逻辑。

不满足上面任何一条，这个入口就退化成一个"看起来能点但没有隔离"的洞。

钉住它的测试：`webreact/tests/learning-space.test.mjs`（admission 与 fail-closed）
与 `webreact/tests/floating-nav.test.mjs`（导航项本身）。

### 红线 4：样式不能外溢

移植层用 Tailwind 4 + 参考项目设计令牌，全部限定在 `.maic-root` 作用域内：

- `webreact/src/styles/maic.css` **只** `@import "tailwindcss/theme.css"` 与
  `tailwindcss/utilities.css`，**绝不能引入 preflight**——那会全局重置
  margin/padding/边框，把站内所有手写 CSS 的页面一起改掉。
- 令牌定义在 `.maic-root { ... }` 内，**不要**提到 `:root`。
- 移植组件本身**不**带 `.maic-root`（为了类名与参考逐字一致），
  由集成层负责加。已有测试钉住这两点。

## 数据与权限

- 每条读写都带 `user_id = ? AND course_id = ?`，归属写进 SQL 的 WHERE，
  不做"取出来再判断"。
- 写操作走 `Idempotency-Key`（防重试重复建）与 `If-Match`（携带 revision，
  防静默回退别人的改动）。
- 409 表示手上副本过期，必须**重新读取**，不能原样重放命令。

## 提交的是命令，不是整份文档

编辑器的写路径提交**命令列表**（`createCommandBuffer`），不是整份文档。
整份回传会让没看到并发修改的作者静默覆盖别人的改动。

## 不要碰的东西

| 路径 | 原因 |
| --- | --- |
| 参考项目（`$REF`，见 `README.md`） | 只读；不要修改它，也不要把它的路径写进提交物 |
| `magicclass-app/` | 上游 v1.0.3，只允许 `scripts/magicclass-brand.mjs` 那一层品牌补丁；**补丁之外的改动即破坏 provenance**（见下节） |
| `.github/workflows/` | CI，除专项任务外不改 |
| 任何 `.env` / 密钥文件 | 不提交、不回显、不进测试夹具 |
| `third_party/magicclass/` 的清单 | 改了要重新生成 SHA 清单，属专项任务 |
| `android/`、`harmony/`、`wx/`、`ml/` | 其它端，本任务不涉及 |

`magicclass-app/` 与"参考项目"是两份东西：`$REF` 是开发机上的只读运行副本、**不入库**；
`magicclass-app/` 是入库的上游源码，路径可以出现在仓库文件里。
