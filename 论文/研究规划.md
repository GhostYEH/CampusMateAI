# 行为识别论文研究规划

更新日期：2026-10-17。状态：已结合参考文件夹 12 篇论文修订，尚未完成预实验。项目现状与数值证据见 [README](README.md)，诊断输入输出见 [第一阶段诊断规范](第一阶段诊断规范.md)，逐篇依据见 [文献对照与方案修订](文献对照与方案修订.md)。下文 [L01]–[L12] 对应参考文件编号。

## 1. 问题定位

建议题目：**面向端侧行为识别的时序证据更新与风险校准**。原题“面向端侧视频行为识别的风险校准与按需时序推理”作为范围描述保留，最终题目由实验决定。

研究对象是冻结的单帧 CNN 与 TSM 两级识别链路。部署时持续执行低成本单帧识别，根据当时及此前可用的信息决定是否调用时序模型，再经过融合、弃权、时序聚合及可能的提醒规则输出结果。

核心问题：在明确错误、覆盖率和召回要求的条件下，能否利用时序证据年龄与在线状态，决定复用、重新计算或弃用证据，并相对无状态风险路由和学习式门控获得更好的质量—运行开销权衡？

文献 [L07] 已明确研究冻结权重后的风险控制早退出，[L10] 已研究双模型选择条件风险路由，[L09] 已使用时间一致性与流式阈值。因此“冻结模型 + 后验阈值 + 两级路由”不再被视为足够的新颖性。新增研究假设是：**在有旧证据复用和事件状态的因果视频链路中，无状态风险分数可能无法正确反映更新与采纳时序证据的价值**。这只是待检验假设，并非已证明的新问题或方法。

### 研究问题与证据

| 问题 | 必须具备的证据 | 不成立时的处理 |
| --- | --- | --- |
| RQ1：两模型是否互补，且仍有可节省成本？ | 成本拆分、现有调用率、纠错／致错统计和预算曲线 | 调整模型或弱化效率主张 |
| RQ2：低成本信息与证据年龄能否预测更新／采纳价值？ | 单纯置信度、时间一致性与状态特征的分组消融；调用纠错／致错及实际成本—质量结果 | 简化为阈值方案，或转向其他问题 |
| RQ3：后验校准能否稳定选择可行运行点？ | 校准与测试隔离；风险超预算情况、覆盖率、召回及不确定性 | 只报告经验结果，或记录无可行候选 |
| RQ4：少量标注与场景变化如何影响校准？ | 固定标注预算、跨组重复、源域／目标域设置和样本量曲线 | 收窄适用范围，不宣称普遍迁移 |
| RQ5：离线成本收益是否反映在设备运行中？ | 实际跳过 TSM 后的延迟、调用次数和可用的能耗测量 | 只报告已测指标，分析固定成本 |
| RQ6：状态依赖设计是否超过已有无状态风险路由？ | 无缓存、固定 TTL、学习式门控、风险路由适配与完整状态策略的配对回放 | 若固定 TTL 或无状态路由已足够，不强行主张新状态策略 |

“冻结模型”是部署约束，不单独构成创新。冻结相同骨干后独立训练轻量门控完全可行，必须纳入对照。所谓“少量标注”也必须用明确的事件、视频或人物预算定义。

## 2. 范围与暂缓项

- 本篇聚焦行为识别，表情与三个状态分支暂不融合进主要方法。
- 不以发明新 CNN／Transformer 主干为目标，不预先把共形预测确定为最终获胜方法。
- 先做公开数据实验；自有前摄场景采集尚不具备条件。
- 暂缓系统触控、亮屏、前台应用和 IMU 先验。当前 `PHONE_USE` 触发来自视觉预测。
- 公共数据回放可以测试设备运行成本，不能替代新设备相机采集条件下的识别泛化验证。
- 新研究产物使用独立目录，沿用现有标签与导出约定；本规划不授权自动替换部署模型、调整生产阈值或改动公开 API。

## 3. 数据、溯源与划分

### 数据分工

| 数据 | 可用目的 | 当前限制与状态 |
| --- | --- | --- |
| 现有 SCB 大学课堂数据 | 流程开发、原策略回放、错误分析 | 只有三个源视频前缀；原始文件是否可读仍需清点；不承担主要泛化结论 |
| 现有 SAV 实验来源 | 阅读／记笔记相关行为补充 | 核对官方标签；正集合标签不能当作四类完整负例；不能验证手机类别 |
| NTU RGB+D RGB 模态 [R6] | 候选受控片段分类基准，包含 reading、writing、play with phone/tablet、type on a keyboard | 未确认取得访问；需申请；NTU60 RGB 约 136 GB；固定机位实验室短片段，不是前摄部署证据 |
| TSU [R7] | 候选连续活动和事件边界评价 | 未确认取得访问；须先核对类别、人物划分、标注及许可；居家固定机位，不是课堂 |
| 其他公开连续视频 | 数据不足时再筛选 | 不将尚未核实的数据集及类别写为已具备条件 |

受控片段分类是可先完成的主实验。仅在取得合适连续视频和时间标注后开展事件级主张；不能把拼接片段当作自然事件流。不得把不相关动作统一映射为 `NO_VISIBLE_STUDY`。`UNCERTAIN` 是模型弃权状态，标注不确定、画质拒绝、类别外行为应单独编码，不作为随意合并的训练类别。

### 溯源与划分原则

1. 清点数据、标签来源、模型来源、训练清单、配置、日志、权重哈希和代码版本。记录原始权重是否接触过拟评测数据；缺失时明确标为未知。
2. 找不到旧训练材料时，用来源明确的预训练权重和新固定划分重建研究基线；旧部署模型保留作内部开发对照。
3. 保留官方测试协议。从训练池划出开发与独立校准部分；模型训练、门控学习、风险校准和最终测试的用途分开。样本不足时明确缩小研究范围，不复用测试集调参。
4. 以人物及源记录为分组约束，同一人物、同一次动作的同步多机位、同一源视频及近重复帧不能跨独立划分。若官方协议允许人物跨组，则单独标记其检验的是跨视角而非人物独立泛化。
5. 时间窗口只使用当前及过去帧。记录采样率、窗口、冷启动、跨视频状态清空和离线片段／在线回放的差异。
6. 文件哈希去重不等于人物隔离；不明人物身份时仅声明源视频分组。
7. 数据访问、磁盘和下载耗时计入排期。只发布许可允许的代码、协议、划分索引或派生统计，不默认重新分发原始视频、人物图像或新数据集。

### 新主线的数据前置条件

证据过期与事件状态的主要结论需要有类别转移的真实连续记录。NTU 等单动作片段可以承担无状态路由复现和机制预实验，不能单独证明跨行为转移时的缓存更新有效性。第 2–3 周先核实连续数据可得性、共享标签语义与独立记录数；仍不可得时，保留受控片段比较，暂缓新主线的事件级／证据过期贡献，不靠拼接数据补成自然场景证据。合成模糊、遮挡、丢帧与顺序扰动只能作为标明构造方式的压力测试。

## 4. 方法设计与理论边界

### 候选方法

先固定单帧与 TSM 权重，在同样的信息和标注预算下比较：校准置信度、概率间隔、预测熵、共形集合信号，以及预测调用价值的轻量门控。门控应同时考虑纠错、致错和成本，而非只识别“困难样本”。

完整策略参数包括触发规则、最小调用间隔、时序结果有效性、融合、弃权、事件进入／退出和冷却。尽量先固定共用的后处理，只比较门控；研究后处理交互时再做独立消融。

### 从一次性路由改为证据更新与采纳

将方法拆成两个可单独验证的决策，避免一开始加入复杂强化学习或在线重训：

1. **调用前：**基于当前单帧分布、短期变化、最近 TSM 证据年龄／有效性、已有类别分歧及事件状态，在“保留现有路径、刷新 TSM、拒用旧证据并按既定规则回退／弃权”中选择。`COMPUTER` 等单帧无法识别的类别需单列覆盖损失，不能把不调用当作无代价。
2. **调用后：**只有实际得到新 TSM 输出，才决定采纳新证据、保留原路径或弃权。新增采纳门控需要明确其拒绝后是保留旧缓存还是使缓存失效，并单独统计成本、纠错与致错。

时间一致性、JSD／类别稳定性信号属于 [L09] 已有思想；“提出纠错再选择”属于 [L12] 已有思想。可借鉴其信号与消融，不能把它们重新命名为原创。可能的贡献只在因果、有缓存状态的刷新／复用机制及其可验证收益，仍需与简单 TTL 和强基线区分。

先固定后处理、比较调用门控，再加入缓存有效期，最后比较调用／采纳联合与分离；若前一步没有收益，不继续堆叠模块。事件状态特征来自预测与系统记录，不读取真实事件边界；禁止使用 [L12] 的完整非因果上下文充当在线门控输入。

### 风险不能混用

| 受控／评估对象 | 含义 | 不能自动推出的结论 |
| --- | --- | --- |
| 共形集合失覆盖概率 | 真实标签未进入候选集合的概率 | 接受样本错误率、每类／每人保证、错误提醒次数 |
| 选择性风险 | 已接受预测中的错误程度；须定义分母与零接受情形 | 总体召回或足够覆盖率 |
| 事件误报与漏检 | 依固定匹配规则衡量事件输出 | 真实提醒错误或自然观察小时率 |
| 实际错误提醒／观察小时 | 明确提醒执行逻辑和有效观察时长后的时间归一化结果 | 不经证明的有限样本保证 |
| 相对参考系统的性能差风险 [L07] | 相对固定完整模型或参考策略的损失增量 | 真实标签错误率达标；参考模型自身也可能错误 |

新增两条统计约束：

- [L10] 的选择条件错误涉及期望接受错误数与期望接受数的比值；它不等于逐会话错误比例的均值，也不是对每个已实现校准集的条件保证。研究工具分别记录分子、分母、零接受情况、总体微平均与会话宏平均，不能借用名称混写。
- [L09] 的无标签时间一致性／分数分位数监测不自动控制真实分类错误；不能把拒绝比例、分数超阈比例或分数覆盖等同于选择后精度。漂移条件下所有真实错误指标仍由保留真值的评测端计算。

普通分裂共形预测 [R1]、CRC [R4] 和 LTT [R5] 的保证对象及条件不同。原始 CRC 针对有界且满足相应单调条件的损失，控制其期望；LTT 可通过多重检验处理候选后处理规则并给出相应风险控制。多参数、有状态策略不一定满足 CRC 的单调性，不能直接套用其结论。

风险校准应针对拟声明的完整最终输出；新增后处理是否保留保证要看损失性质，不能一概认定有效或无效。优先以完整独立会话／人物记录构造校准单位，固定会话边界和状态初始化；同一人物内的事件不是自动独立或可交换的样本。无独立会话或相应假设依据时，只做经验校准。

若要研究时间归一化期望率，可探索固定时长会话上的有界损失，再核对定理条件；不得把“时间率绝不可能有保证”或“有 CP 即保证每小时误提醒”作为结论。理论推导单独审查，尚未完成。

采用完整策略族时，候选集合在风险校准前固定；从许多参数中挑选必须处理多重选择。若校准后无可行候选，报告无可行运行点，不临时扩大风险预算。每类、每人物、时间均匀保证与域偏移保证均需另外论证。

## 5. 公平对照与运行点

| 对照 | 目的 |
| --- | --- |
| 单帧、单帧加平滑 | 判断基础性能及平滑贡献 |
| 固定频率 TSM，多档频率 | 常规预算—质量参照；恒调用只是其中一个端点，不是质量上界 |
| 当前启发式策略 | 检验相对实际系统还有多少收益 |
| 置信度／间隔／熵门控 | 检验简单信号是否足够 |
| 冻结相同骨干的学习式门控 | 必做强对照；同样信息、标注预算和候选选择规则 |
| 共形集合触发 | 检验校准集合是否有额外价值 |
| 固定 TTL、仅按年龄刷新 | 排除简单缓存过期机制已能解释全部收益 |
| Fast yet Safe 风格的性能差／一致性风险阈值 [L07] | 最接近的冻结后验风险控制对照；不满足单调等条件时不声称原定理保证 |
| LEC 风格双模型路由 [L10] | 最接近的无状态选择条件风险对照；先在共同标签片段设置实现，完整流式版单列适配 |
| 时间一致性监测／动态阈值适配 [L09] | 使用相同可见信息的流式信号基线，冻结骨干版本不能冒称包含 TA 训练的完整复现 |
| 最终拟提策略 | 与以上对照比较完整增益及新增成本 |
| 事后 oracle 参照 | 诊断机会空间，不是可部署方法，也不计入实际方法排名 |

LiteEval [R3]、FrameExit [R2] 为学习式条件计算的重要相关工作。若只在现有级联上实现其思想的门控，应明确标为适配基线，不能声称完整复现原论文。

对照分三级执行以控制工作量：**必做**为简单阈值、现有策略、固定 TTL、学习式门控、[L07]／[L10] 的适配及最终策略；**针对性消融**为 [L09] 风格时间信号和调用／采纳分离；**扩展**才考虑 [L08] 的在线 UCB 阈值适配。[L08] 定理依赖可靠性函数近似条件，且原方法包含退出／可靠性训练，不能声称在冻结骨干、任意漂移下无标签保证真实错误。EdgeOAR、Uni-AdaFocus、E4、MMEdge 的完整系统重建不列为首轮必做。

同一批模型输出可用于开发阶段回放，但每种策略需维护自己的缓存与状态；离线预计算的未来信息不得进入在线门控。单帧四类与时序五类须先声明共同评价空间、额外类别及对应策略能力，不能静默删除 `COMPUTER` 或把它当负类。

统一运行点选择规则：在预先定义的错误、覆盖率、关键类别召回和延迟要求下，选择满足条件的最低成本候选；并列时按事先固定规则决胜。开发集设计候选，独立校准集执行适当的风险筛选，测试集只评价锁定候选。报告完整曲线，同时比较相近成本下的质量及相近质量下的成本。

## 6. 指标、统计与设备基准

- 片段／分类：Macro-F1、balanced accuracy、每类 precision／recall、选择性风险、接受覆盖率和拒绝原因。
- 连续事件：固定类别集合及匹配规则，报告事件 precision／recall／F1、错误事件数、漏检数和真实确认延迟。主 tIoU 可沿用现有 0.30 作候选，并预先规定 0.10／0.50 的敏感性分析；最终配置待锁定。
- 延迟只对匹配事件计算时，必须同时显示匹配数量和漏检，避免漏掉困难事件后得到漂亮延迟。
- 实际提醒：单独记录提醒发出与冷却抑制，区分错误预测事件和错误提醒；分母使用所有预定有效观察时长，不能只计接受预测的时长。
- 汇总要区分总体、按人物／会话平均；固定时长回放、自然连续视频和人工拼接压力测试分别命名。
- 同一记录上做配对比较，以人物或最高层独立源记录为聚类重采样单位，每次重新计算总体非线性指标。报告差值与置信区间，事先规定主要比较及多重比较处理。
- MDE／功效由开发预实验及明确假设估计，不由帧数推断，也不使用最终测试结果反向选择目标。只有少数独立视频时，bootstrap 不能弥补信息不足。
- 固定骨干只训练门控时，区分门控随机种子、划分变化与设备运行重复；模型不重训时不虚构多次骨干训练。
- 设备端必须实际跳过未触发的 TSM。统一解码、输入节奏、画面尺寸、线程、加速器、预热、显示状态和测量窗口，随机化／平衡方法执行顺序，记录温度与失败。
- 公共处理、帧复制、ROI 检测、缓存、门控、单帧及 TSM 预处理均计入。预算与耗时／能耗单位一致；GPU／CPU 重叠时不能用简单加法代替实测。
- 有可靠功耗条件才报告能量；否则只报告延迟、吞吐、调用次数等已测结果。相同输入在不同手机回放是运行迁移，不是新相机视域泛化。
- 时序证据：按年龄分箱报告样本量、复用错误、刷新纠错／致错，单列真实行为转移前后和稳定段；真值边界仅在评测中用于分层。记录拒用旧证据的覆盖损失和恢复耗时。
- 调用与采纳：同时报告 TSM 调用率、新结果采纳率、计算后被拒比例、无效调用成本和固定 TTL 基线。发现错误的 AUC 高不等于能产生有益修正 [L12]。
- 时间：除推理内核耗时外，分开报告采样窗口等待、冷启动、排队、预处理、确认／调度和端到端延迟。借鉴 [L01]／[L05] 的系统视角，不将观察更少帧的收益全算成内核加速。
- 共形：报告真实标签覆盖与集合均值／分位数大小、空集合／全集合／单元素比例；大集合的高覆盖不能作为可靠识别证据 [L12]。
- 设备测量：参考 [L03] 区分功率 W 与能量 J／每观察分钟能量；锁定或记录 governor、温度与功耗模式。首轮不引入手机未开放的 DVFS 控制，也不照搬 Jetson 节能百分比。

当前评价实现存在需先核对的两个定义问题：未匹配手机事件被命名为 `false_reminders_per_hour`，但不一定实际发出提醒；事件起点可回填至候选开始，不能代替确认发出时间。见 [事件指标](../ml/behavior_recognition/src/behavior_recognition/metrics.py)、[聚合器](../ml/behavior_recognition/src/behavior_recognition/temporal.py)。本规划尚未修改它们。

## 7. 首轮排期与检查点

以下按数据和环境具备后的约 10–12 周工作量估计，不是已确认交稿日期。公开数据申请可提前进行，不假设一定获批。

| 阶段 | 工作 | 验收与下一步 |
| --- | --- | --- |
| 第 1 周 | 最接近文献差异表、溯源、成本初测、当前调用率／旧证据年龄 | 不再把冻结后验风险路由本身列为创新；成本注明设备／单位 |
| 第 2–3 周 | 连续数据可得性核实、固定分组、双模型预测与有状态回放 | 没有真实连续转移数据时先做片段对照，暂缓证据过期主张 |
| 第 4 周 | 互补性、按年龄及转移分层、TTL 对照、事后参照与精度预估 | 若简单 TTL 已足够或独立数据不足，收窄方法与结论 |
| 第 5–6 周 | 学习门控、[L07]／[L10] 适配、时间信号、统一运行点 | 原方法／适配区别明确，理论前提不满足时仅经验比较 |
| 第 7–8 周 | 调用／采纳与状态消融、独立校准、小标注／域变化 | 区分性能差、真实错误和选择后风险；无可行点如实记录 |
| 第 9–10 周 | 设备回放与重复测量 | 开销包含公共路径；功耗不可测时弱化能耗声明 |
| 第 11–12 周 | 锁定代码／参数后最终测试、论文初稿 | 贡献—证据逐项对应，按实际结果选投稿渠道 |

## 8. 当前贡献假设与写作结构

可验证后再主张的贡献：面向旧证据复用的因果时序更新／采纳策略；状态改变后完整输出的经验或条件成立时的风险校准；统一预算约束下的可复现评价与设备运行证据。后验风险早退出 [L07]、时间一致性不确定性 [L09]、双模型选择条件路由 [L10]、选择性修正 [L12] 都不再单独作为原创。若新状态机制没有超过固定 TTL、学习门控和无状态风险适配，题目应退回经验比较／失败边界研究，并重新评估投稿可行性。

若共形策略没有优于简单或学习式门控，转为研究其样本效率、预算可行性和失败边界，或选择证据更强的策略；不强行保留预设方法名。若收益很小且统计精度不足，应扩大独立数据或收窄结论。

论文结构：引言（部署问题与可检验假设）→ 相关工作（条件计算、选择预测、校准）→ 方法（状态、信息、目标与保证边界）→ 实验协议 → 结果与消融 → 局限。建议图表为成本分解、模型互补性、质量—成本曲线、风险—覆盖曲线、校准样本量曲线和设备结果。

投稿前必须具备公平强基线、可复现来源、锁定测试、独立单位数量、失败案例及实际运行证据。未经进一步系统检索不写“首次”；没有实验与统计支持不写“显著”，没有独立前摄数据不写部署泛化已验证。

## 9. 已核查文献入口

以下为针对性核查入口，不是系统综述；版本与正式出版信息在投稿前再次核实。

参考文件夹的 12 篇以 [文献对照与方案修订](文献对照与方案修订.md) 为索引，使用 [L01]–[L12] 标识并保留本地文件、原文版本与定位。优先深入 [L07]、[L10]、[L09]、[L12]、[L08]；以下 [R1]–[R10] 为此前核查的背景资料，两组编号不混用。

- **[R1]** Tim Bary 等，*Conformal Predictions for Human Action Recognition with Vision-Language Models*，2025：[原文](https://arxiv.org/html/2502.06631v1)。提供 HAR 预测集合覆盖与集合规模相关研究，不能作为事件误提醒保证的依据。
- **[R2]** *FrameExit: Conditional Early Exiting for Efficient Video Recognition*，CVPR 2021：[官方页面](https://openaccess.thecvf.com/content/CVPR2021/html/Ghodrati_FrameExit_Conditional_Early_Exiting_for_Efficient_Video_Recognition_CVPR_2021_paper.html)。条件早退出与学习式门控的重要对照。
- **[R3]** *LiteEval: A Coarse-to-Fine Framework for Resource Efficient Video Recognition*，NeurIPS 2019：[原文入口](https://arxiv.org/abs/1912.01601)。粗细特征与条件门控，不应忽略学习式计算分配先例。
- **[R4]** *Conformal Risk Control*：[原文入口](https://arxiv.org/abs/2208.02814)。核对损失、有界性、单调性、抽样假设与期望控制范围。
- **[R5]** *Learn then Test: Calibrating Predictive Algorithms to Achieve Risk Control*：[原文入口](https://arxiv.org/abs/2110.01052)。候选后处理策略的风险检验路线，不要求重新拟合底层模型。
- **[R6]** NTU RGB+D / NTU RGB+D 120：[官方数据页](https://rose1.ntu.edu.sg/dataset/actionRecognition/)。类别、RGB 规模、申请及使用条款以官方说明为准。
- **[R7]** *Toyota Smarthome Untrimmed: Real-World Untrimmed Videos for Activity Detection*：[原文入口](https://arxiv.org/abs/2010.14982)。连续活动及时间边界评价的候选数据来源。
- **[R8]** *Efficient uncertainty aware human activity recognition on microcontrollers using hyperdimensional computing and conformal prediction*，Scientific Reports，2026：[出版页面](https://doi.org/10.1038/s41598-026-57375-8)。IMU 与微控制器路线，说明端侧 HAR、不确定性与效率的组合已有先例。
- **[R9]** *AdaFrame: Adaptive Frame Selection for Fast Video Recognition*，CVPR 2019：[官方页面](https://openaccess.thecvf.com/content_CVPR_2019/html/Wu_AdaFrame_Adaptive_Frame_Selection_for_Fast_Video_Recognition_CVPR_2019_paper.html)。自适应选帧背景。
- **[R10]** *Real-Time Video Inference on Edge Devices via Adaptive Model Streaming*，ICCV 2021：[官方页面](https://openaccess.thecvf.com/content/ICCV2021/html/Khani_Real-Time_Video_Inference_on_Edge_Devices_via_Adaptive_Model_Streaming_ICCV_2021_paper.html)。服务器持续蒸馏与端侧更新，区别于纯本地冻结级联触发，不列为最接近的门控基线。
